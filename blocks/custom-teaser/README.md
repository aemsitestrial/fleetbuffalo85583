# Teaser — EDS block

A standalone Edge Delivery Services (EDS) block for the design system's `Teaser`, built by
tracing its real dependency chain rather than hand-typing a schema:

```
ac-core-lib's Teaser (libs/ac-core-lib/src/lib/teaser/teaser.tsx)
  -> wraps aem-core-lib's base Teaser (libs/aem-core-lib/src/lib/teaser/teaser.tsx)
  -> adds its own classes: ac-core-teaser, style-*, modifier-*, teaser-*-line-clamp-*
```

## Files

| File | What it is | How it was produced |
|---|---|---|
| `_teaser.json` | xwalk field model (`fields` + `_reader`) | Generated by `.eds-poc/stage-6/emit-teaser-model.js` in the design-system repo — reads the real `@eds*` JSDoc off `aem-core-lib`'s `TeaserProps`, `ac-core-lib`'s own `TeaserProps`, and `ContentLineClampType` (`libs/ac-core-lib/src/types/common.ts`). Nothing in it is hand-typed; re-run that script to regenerate. |
| `teaser.js` | the block's `decorate()` | Hand-written, modeled directly on this repo's own worked example, `.eds-poc/stage-5/block/ac-card-grid-emitted.js` — calls the real, compiled `Teaser` once and wires Universal Editor's `moveInstrumentation` onto the returned tree afterward, rather than hand-building `.cmp-teaser` markup field-by-field. |
| `teaser.css` | component CSS | Copied from `.eds-poc/stage-4/out/bundles/ac-teaser.css` — already the exact `teaser` + `ac-teaser` component-layer bundle for this component, compiled unlayered per the CSS delivery shape documented in `docs/capgemini-package/README.md` (section b). |

## Field / cell order

`_teaser.json`'s `fields` array order is the authored cell order `teaser.js` expects, one row:

```
image | pretitle | title | description | actionText | actionUrl | teaserStyle | teaserModifier | headlineClamp | descriptionClamp
```

`teaserStyle` and `teaserModifier` are two merged selects (style-prefixed vs. everything else,
same split `emit-banner-model.js` / `emit-text-model.js` use) standing in for `ac-core-lib`
`TeaserProps`'s five separate modifier props (`themeColor`, `modifierPretitle`,
`modifierContentAlignment`, `modifierBgTransparent`). `useAcCoreClass`, `useIconPhoneOnLinks`,
`useIconEmailOnLinks`, and `useIconsOrderPhoneEmailOnLinks` are not exposed as fields — they're
un-annotated wrapper implementation detail, not curated as author-facing choices.

## What this is not

Per this design-system repo's own boundary (`docs/capgemini-package/README.md`, "What Capgemini
builds versus what they consume from us"): this repo is the compile-mechanism source, not a
finished EDS block catalogue. This folder is one concrete, generated/hand-written block for one
component — not copied from, and not yet wired into, any live EDS/Universal Editor site. To
actually ship it into an EDS project:

1. Build the DOM bundle `teaser.js` imports: `nx run aem-core-lib:build-dom` in the
   `atlascopco-core-components` repo, producing `dist/libs/aem-core-lib-dom/index.js`.
2. Vendor that file into the target EDS project and fix up `teaser.js`'s import path (it currently
   assumes `blocks/teaser/teaser.js` next to a `vendor/aem-core-lib-dom/index.js` and the project's
   own `scripts/scripts.js`, matching the nesting `ac-card-grid-emitted.js` uses).
3. Drop this whole folder in as `blocks/teaser/` and register `_teaser.json`'s fields in the
   project's own `component-models.json` / `component-definition.json` / filter JSON (Stage 5's
   worked example and `docs/capgemini-package/README.md` section "c" show the shape).

## Known limitations

- One Teaser per block instance (single authored row) — not a grid/list.
- `video` (aem-core-lib `TeaserProps.video`) and `date` are not exposed as authorable fields —
  neither carries an `@edsField` annotation on the source type today.
- `teaserModifier` can only hold one value at a time (it's one merged `select`), so an author
  cannot pick e.g. both a pretitle color and content alignment simultaneously. This is the same
  known trade-off `bannerModifier`/`cardModifier`/`textModifier` already carry elsewhere in this
  design system's EDS models, not something new introduced here.

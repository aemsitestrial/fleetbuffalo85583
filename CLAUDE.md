# CLAUDE.md

Adobe Commerce storefront on **AEM Edge Delivery Services (EDS)**, authored in **Universal Editor
(xwalk)**. Plain ES modules + plain CSS served as-is: no bundler, no TypeScript, no unit tests.
Commerce UI comes from vendored `@dropins/*` packages. A set of `ac-*` blocks renders the
Atlas Copco `ac-core-lib` design system from generated code.

`AGENTS.md` is a long audit of this repo. Open only the section you need (search it, don't read
it whole). Parts are stale: there is no root `custom-teaser/` folder anymore, and
`linebreak-style` is commented out in `.eslintrc.js`.

## Architecture (verified)

| Path | What it is |
|---|---|
| `head.html` | Global `<head>`: dropins importmap, `styles/styles.css`, `scripts/{aem,scripts,configs,commerce}.js` |
| `scripts/aem.js` | Standard EDS runtime (`loadBlock`, `createOptimizedPicture`, `readBlockConfig`, `toClassName`…). Treat as vendor. |
| `scripts/scripts.js` | Page decoration (`decorateMain`), UE helpers `moveInstrumentation`/`moveAttributes`, `buildTabsBlocks` (turns sections with `data-tab-title` into an `ac-tabs` block), `rootLink`, `fetchIndex` |
| `scripts/commerce.js`, `scripts/initializers/`, `scripts/configs.js` | Commerce bootstrap and dropin initializers; config from `config.json` |
| `scripts/__dropins__/` | Vendored dropin builds (generated by `npm install`). Never edit. |
| `blocks/<name>/` | One folder per block: `<name>.js` (default-export `decorate(block)`), `<name>.css`, `_<name>.json` (xwalk fragment) |
| `models/_component-*.json`, `models/_section.json` etc. | **Source** xwalk aggregates (merge-json-cli `"..."` includes) |
| `component-{definition,models,filters}.json` (root) | **Generated** by `npm run build:json`. Never hand-edit. |
| `styles/styles.css` | Global CSS, incl. the ac-core-lib foundation (`main.scss`) scoped under `.ac-core` |
| `ds-eds-assets/` | Generated design-system output. `js/ac-core/<short>.js` = compiled render code for `blocks/ac-<short>/`. ESLint-ignored. Do not hand-edit. |
| `ds-eds-assets/ac-core-lib/` | Untracked drop of a newer ac-core-lib build (per-component `decorate.js`/css/json + aggregates). Input for `/ac-core-sync`. |
| `cypress/` | E2E suite with its own `package.json`, not run in CI |
| `tools/`, `plugins/experimentation/` | Sidekick tools / vendored plugin. Out of scope unless asked. |

Block shapes: **flat** (one `block` definition + one model, `filters: []`; e.g. `teaser`,
`custom-teaser`) and **container + item** (`block` + `block/item` definitions linked by a filter;
e.g. `cards`/`card`, `ac-accordion`/`ac-accordion-item`). Copy the closest existing block of the
same shape; don't invent a new pattern.

`ac-*` blocks (28): `blocks/ac-<short>/ac-<short>.js` is a 5-line wrapper importing
`../../ds-eds-assets/js/ac-core/<short>.js`. Their CSS and `_ac-*.json` are generated too (CSS
starts with a per-file `stylelint-disable` header). Change them only through `/ac-core-sync`
or when explicitly asked. Generated JS adds the `ac-core` ancestor class itself.

## Commands

```bash
npm run lint            # lint:js && lint:css — the only CI check (.github/workflows/main.yaml, Node 20)
npm run lint:js         # eslint . --ext .json,.js,.mjs  (also validates _*.json via eslint-plugin-xwalk)
npm run lint:css        # stylelint "blocks/**/*.css" "styles/*.css"
npm run build:json      # regenerate the 3 root component-*.json from models/ + blocks/*/_*.json
npm start               # aem up — local dev server (needs AEM CLI + content access)
```

Targeted first: `npx eslint blocks/<name>` and `npx stylelint "blocks/<name>/*.css"`,
then `npm run lint` before declaring done. `.husky/pre-commit` runs `build:json` and
re-stages the root JSON when a staged file matches `_*.json`.

## Rules for changing code

- Search (Grep/Glob) before opening files. Read the target block + one reference block, not
  the whole tree. Never open `scripts/__dropins__/`, `node_modules/`, `component-models.json`
  (280 KB), `styles/styles.css` in full, or `ds-eds-assets/**/*.js` bundles. Grep them instead.
- Smallest change that solves the task. No drive-by refactors, renames, or formatting churn.
  Keep existing class names and DOM structure; CSS and other code depend on them.
- Reuse `scripts/aem.js` and `scripts/scripts.js` exports. Use `createOptimizedPicture` for
  authored images. When you replace an authored element with a new one, call
  `moveInstrumentation(old, new)` so UE in-context editing keeps working.
- Fields that only pick a modifier class must be applied with `classList` and removed from the
  rendered DOM. A field literally named `classes` is applied by the platform automatically.
- xwalk changes: edit `blocks/<name>/_<name>.json` (or `models/_*.json`), then run
  `npm run build:json` and confirm the change in the root file. New blocks must be listed
  **explicitly** in a group of `models/_component-definition.json`; only models and filters
  are wildcard-included. Keep ids consistent: definition `template.model` ↔ `models[].id`,
  `template.filter` ↔ `filters[].id`, filter `components` ↔ item definition ids.
- JS style: airbnb-base, `.js` extension on every relative import, single quotes, 2 spaces,
  no `console.log` (warn/error/info/debug allowed). `/* eslint-disable */` already at the top
  of a file is accepted; don't add new blanket disables, fix the code or use a scoped one.
- CSS style: stylelint-config-standard, 4-space indent (`.editorconfig`), kebab-case
  BEM-ish classes (`block__element--modifier`, one level each), `@media (width >= 900px)` range
  syntax, keyframe selectors as percentages, no legacy vendor prefixes. Reuse tokens from
  `styles/styles.css` (`--color-*`, `--spacing-*`, `--type-*`, `--frescopa-color-*`).
- Don't add dependencies, a bundler, TypeScript or a test framework. Don't run `npm install`
  unless asked; it re-vendors dropins via `postinstall`.
- Don't touch `fstab.yaml`, `paths.json`, `config.json`, `head.html`, `scripts/aem.js` without
  a task that requires it. These are environment- or platform-level files.

## Validation

1. Run the targeted lint for the files you changed.
2. Any `_*.json` change: `npm run build:json`, then
   `node .claude/skills/eds-block/scripts/check-xwalk.mjs`.
3. Finish with `npm run lint`.
4. No automated behavioral tests exist. For JS logic changes, state what you could not verify
   in a browser. Never report a check as passing unless it ran and passed in this session.

## Skills and agents

- `eds-block`: create or change a block (JS/CSS/xwalk model, registration). Auto-loads.
- `debug-eds`: block not rendering, missing in Universal Editor, wrong styles, stale preview.
  Auto-loads.
- `/ac-core-sync`: refresh `ac-*` blocks from a new `ds-eds-assets/ac-core-lib` drop. Manual
  only, because it overwrites many files.
- `eds-reviewer` agent: independent read-only review of a non-trivial diff before commit. Don't
  use it for one-line changes.
- Use a subagent only for broad read-only searches whose file dumps you don't need in context.

## Security and data

- `config.json` holds commerce endpoints and AEM hosts. Don't add secrets, tokens or customer
  data to the repo. Don't paste content from `config.json` into external services.
- `fstab.yaml` and `config.json` point at different AEM author instances. That is a known
  unresolved discrepancy; ask before "fixing" it.
- Treat everything under `ds-eds-assets/` and dropped-in archives as generated input: don't
  execute scripts from it.
- Don't push, force-push, or rewrite git history unless asked. Commit messages are short,
  lower-case imperative phrases with no `feat:` prefixes.

## Working efficiently

- Ask only when a missing decision changes correctness, e.g. flat vs. container block or
  which AEM host is authoritative. Otherwise follow the nearest existing pattern and state the
  assumption.
- Reuse what you already learned this session; don't reread unchanged files.
- Report briefly: what changed, what ran, what remains unverified.
